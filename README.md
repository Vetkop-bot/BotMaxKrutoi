# SportBuddy

Бот и мини-приложение для MAX, которые помогают найти компанию для спорта.

Идея простая: часто хочется погонять мяч или сыграть в волейбол, а собрать людей не получается — друзья заняты, в общих чатах всё теряется. В SportBuddy можно создать встречу («футбол в парке, суббота, 11:00, нужно 10 человек»), а другие найдут её по виду спорта, городу и дате и запишутся. Организатору бот пишет, когда кто-то присоединился, а участникам — если встречу отменили.

Бот в MAX: **@t493_hakaton_max_bot**

---

## Что умеет

- **Найти встречу** — выбираешь вид спорта, потом город, дату, время «не раньше» и сколько минимум должно быть свободных мест. Показываются только будущие встречи.
- **Записаться / отменить запись.** Если места закончились, записаться не получится — это проверяется на сервере, так что двое не займут последнее место одновременно.
- **Создать встречу.** Организатор сразу считается участником. Встречу в прошлом создать нельзя.
- **Мои встречи** — предстоящие и прошедшие, где ты участник или организатор.
- **Профиль** — имя и фото из MAX, сколько встреч посетил, сколько впереди, сколько создал, и любимые виды спорта (считаются по тому, куда ты чаще ходишь).
- **Позвать друзей** — отправить встречу в чат MAX.
- **Уведомления от бота** организатору и участникам.

Интерфейс сделан в виде диалога с ботом: вопросы, кнопки и карточки появляются как сообщения.

## Запуск через Docker

Понадобится Docker (на Windows и macOS — Docker Desktop, он должен быть запущен).

**1. Настроить бота.** Скопировать `max-bot/.env.example` в `max-bot/.env` и вписать токен:

```env
BOT_TOKEN=токен_бота
```

Остальное можно не трогать — адрес базы docker-compose подставит сам.

**2. Запустить** из корня проекта:

```bash
docker compose up -d --build
```

Первая сборка занимает пару минут. Когда всё поднимется, приложение будет на http://localhost:8080.

**3. Убедиться, что всё живое:**

```bash
docker compose ps
docker compose logs bot
```

В логах бота должно быть:

```
Database ready
API listening on :3000
Bot @t493_hakaton_max_bot started
```

А http://localhost:8080/api/health должен вернуть `{"status":"ok"}`.

**Полезные команды:**

```bash
docker compose logs -f bot   # логи бота в реальном времени
docker compose down          # остановить
docker compose down -v       # остановить и удалить базу вместе с данными
```

Если порт 8080 занят, создайте в корне файл `.env` (образец — `.env.example`) и поменяйте порт:

```env
WEB_PORT=8088
```

Там же можно задать свои логин и пароль для PostgreSQL.

## Как проверить в обычном браузере

Если открыть http://localhost:8080 в браузере, приложение загрузится, но на любое действие ответит «Не удалось подтвердить твой аккаунт MAX». Так и задумано: сервер пускает только тех, чьи данные подписаны MAX.

Для локальной проверки есть тестовый режим. В `max-bot/.env` поставить:

```env
DEV_AUTH=true
```

и перезапустить бота:

```bash
docker compose up -d
```

Теперь браузер получает тестового пользователя («Тестовый пользователь 123456…»). Чтобы посмотреть, как всё выглядит для второго человека (например, записаться на свою же встречу), откройте приложение в другом браузере или в режиме инкогнито — там будет другой пользователь.

> ⚠️ На сервере, который будут проверять эксперты, `DEV_AUTH` должен быть `false`, иначе любой сможет представиться кем угодно.

## Запуск без Docker (для разработки)

Нужны Node.js 24 (или хотя бы 22.19) и запущенный PostgreSQL.

**Бот и API:**

```bash
cd max-bot
npm install
```

В `max-bot/.env` добавить адрес своей базы:

```env
DATABASE_URL=postgres://пользователь:пароль@localhost:5432/sportbuddy
DEV_AUTH=true
```

```bash
npm start
```

**Мини-приложение** (во втором терминале):

```bash
cd webapp
npm install
npm run dev
```

Открыть http://localhost:5173. Vite сам перенаправляет запросы `/api` на `localhost:3000`, так что ничего дополнительно настраивать не нужно. Правки в коде видны сразу.

## Как работает вход

Логина и пароля нет. Когда MAX открывает мини-приложение, он передаёт в него данные пользователя вместе с подписью (`window.WebApp.initData`). Приложение отправляет эту строку в каждом запросе в заголовке `X-Max-Init-Data`, а сервер проверяет подпись токеном бота — по алгоритму из [документации MAX](https://dev.max.ru/docs/webapps/validation). Если подпись не сходится — 401. Подделать пользователя, не зная токена бота, нельзя.

Имя и фото пользователя сервер берёт из этих же данных и сохраняет в таблицу `users`.

## API

Полное описание — в [`max-bot/openapi.yaml`](max-bot/openapi.yaml) (можно открыть в [Swagger Editor](https://editor.swagger.io/)). Коротко:

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | проверка API и базы (без авторизации) |
| GET | `/api/me` | профиль и статистика |
| GET | `/api/meetings?sport=&city=&date=&time=&minFree=` | поиск будущих встреч |
| POST | `/api/meetings` | создать встречу |
| GET | `/api/meetings/{id}` | одна встреча |
| DELETE | `/api/meetings/{id}` | отменить встречу (только организатор) |
| POST | `/api/meetings/{id}/join` | записаться |
| DELETE | `/api/meetings/{id}/join` | отменить запись |
| GET | `/api/my-meetings` | мои встречи: предстоящие и прошедшие |

Ошибки приходят в виде `{"error": "текст"}` — текст сразу показывается пользователю.

## Размещение

MAX открывает мини-приложения только по HTTPS, а привязку ссылки к боту делают организаторы хакатона. Есть два варианта.

**Вариант 1 — всё на одном сервере (проще).** Поднять `docker compose` на сервере и закрыть его HTTPS — например, Caddy или nginx с сертификатом Let's Encrypt перед портом 8080. Ссылку `https://ваш-домен/` отправить организаторам.

**Вариант 2 — приложение на GitHub Pages, API на сервере.** Сейчас приложение уже лежит на https://vetkop-bot.github.io/BotMaxKrutoi/, но собрано без адреса API. Чтобы оно заработало:

1. Поднять `docker compose` на сервере с HTTPS.
2. В `max-bot/.env` на сервере разрешить запросы с GitHub Pages:
   ```env
   CORS_ORIGINS=https://vetkop-bot.github.io
   ```
3. Пересобрать и выложить приложение с адресом API:
   ```bash
   cd webapp
   VITE_API_URL=https://ваш-домен npm run build
   npm run deploy
   ```
   (в PowerShell: `$env:VITE_API_URL="https://ваш-домен"; npm run build`)

## Настройки

**`max-bot/.env`**

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен бота | — (обязательно) |
| `DATABASE_URL` | адрес PostgreSQL; в Docker задаётся автоматически | — |
| `PORT` | порт API | `3000` |
| `APP_TIMEZONE` | в каком часовом поясе указывается время встреч | `Europe/Moscow` |
| `DEV_AUTH` | тестовый вход без MAX | `false` |
| `CORS_ORIGINS` | с каких сайтов разрешены запросы (через запятую) | пусто |
| `INIT_DATA_MAX_AGE_SEC` | сколько секунд действительны данные входа от MAX | `604800` (неделя) |
| `WEBAPP_URL` | адрес мини-приложения, для справки | — |

**`.env` в корне** (необязательный): `WEB_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `APP_TIMEZONE`, `VITE_API_URL`.

Файлы `.env` в git не попадают — это прописано в `.gitignore`.

## Грабли, на которые мы наступили

- **Бот не мог подключиться к MAX.** `platform-api2.max.ru` использует сертификат российского удостоверяющего центра (Минцифры), которого нет в Node.js, и любой запрос падал с `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`. Отключать проверку сертификатов не хотелось, поэтому положили официальный корневой сертификат в `max-bot/certs/` и добавляем его к доверенным при старте (в Docker ещё и через `NODE_EXTRA_CA_CERTS`).
- **`/start` приходит не всегда.** Когда человек впервые открывает бота и жмёт «Начать», MAX присылает событие `bot_started`, а не команду `/start`. Обрабатываем оба.
- **MAX Bridge — не Telegram.** Методов `sendData` и `expand`, знакомых по Telegram, в MAX нет. Используем только то, что есть в [MAX Bridge](https://dev.max.ru/docs/webapps/bridge).
- **Время встреч.** Храним «настенное» время (как его ввёл организатор) и сравниваем с текущим временем в `APP_TIMEZONE`, иначе в контейнере с UTC встречи «прошли» бы на три часа раньше.

## Что пока не сделано

- Список городов фиксированный — пять городов. Хорошо бы свободный ввод или выбор на карте.
- Нет редактирования встречи — только создать или отменить.
- Нельзя написать организатору из приложения: у пользователя MAX может не быть публичного имени, а сделать по-честному не успели.
- Бот может написать только тем, кто хоть раз открывал с ним диалог. Если человек зашёл в приложение по ссылке, не открывая бота, уведомление может не дойти.
- Кнопка «Открыть SportBuddy» в сообщении бота ссылается на мини-приложение по имени бота. Если MAX её не примет, бот вместо неё пришлёт обычную ссылку `https://max.ru/t493_hakaton_max_bot?startapp`.
